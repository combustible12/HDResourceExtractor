# 下载核心行为与验收规则

本轮用户目标：图片能实际保存、大视频能完整保存、应用内能升级。代码存在、编译通过和真机下载成功是三个不同状态，不得混写。

## 统一下载流程

- 普通图片/音视频文件、静态 HLS、静态 DASH 使用同一个持久任务表与两任务并发队列。
- 所有新任务保存 URL、类型、User-Agent、Referer、对应 Cookie、文件名、备用图片地址。
- 排队、下载中、暂停、失败、取消、完成分别记录；暂停保留缓存，取消禁止旧执行实例重新启动。
- 文件数据流式落盘，普通文件与分段请求均校验响应长度。媒体发布前识别实际格式，拒绝将登录网页标记为图片下载成功。
- 小红书原图地址改写失败时，使用同一图片已观察到的网页地址作为备用；不跨图片猜测替换地址。

## 中断与缓存

- 缓存置于内部 files/downloads，而不是可由系统随时清理的 cache。
- 每个文件/片段记录 URL 和 Range 身份、字节数、SHA-256、服务端验证器和完成状态。
- 下载期间每两秒写入持久检查点；进程中断后丢弃检查点后的未确认尾部，校验确认部分后再续传。
- 普通文件使用 Range 与 If-Range；响应验证器变化、416 或服务器忽略 Range 时重新取数据，禁止将新旧内容直接拼接。
- 对显式字节范围，服务器忽略 Range 时从完整响应流中跳过前缀并截取目标范围。
- 合并失败保留完整片段；重试合并先校验缓存，避免重新下载有效片段。
- 前台服务在 Activity 退出后继续，通知显示任务进度；持久 JobScheduler 任务负责进程被回收后的恢复。
- 用户主动暂停的任务保持暂停；完成或取消后的缓存可清理。Android 强行停止应用后，需再次打开应用恢复，不能宣称能绕过系统限制。

## DASH 与 HLS

- DASH 支持静态非加密 MPD 的 SegmentList、SegmentTemplate、SegmentTimeline、完整 SegmentBase 资源及多 Period。
- 处理 MPD/Period/AdaptationSet/Representation 的 BaseURL 与寻址继承；较近的寻址方式覆盖不同的父级方式。
- 支持 Initialization.range 与 SegmentURL.mediaRange，支持负重复时间轴与 presentationTimeOffset 边界。
- HLS 支持非加密 VOD、主播放列表、独立音频、字节范围、初始化段和不连续段分组。
- 合并使用共有时间原点，保留音视频初始偏移，按时间交织样本，处理大幅时间戳回退。兼容的 Period 顺序拼接。
- MP4/WebM 使用对应原生封装器；设备不支持的编码、不同 Period 编码参数变化、直播和 DRM 不在“通用兼容成功”的承诺内。此时明确失败并保留缓存，不发布坏文件。本轮不含通用转码器。

## 去重与保存

- URL 身份规范化协议/主机/默认端口/路径，保留所有查询参数，避免合并不同内容。
- 相同身份的排队/运行/暂停任务禁止重复创建；失败任务复用任务记录。
- 已保存身份禁止重复下载；发布时另以完整文件 SHA-256 去重，避免不同 URL 保存相同字节。
- 同名不同资源使用身份后缀并按实际格式命名，不依赖原文件名判断内容。
- 不宣称仅凭 URL 可以识别所有跨 CDN、不同签名或不同封装的同一视频。

## 应用内升级

- 首页保留一键检查并升级入口，通过正式 GitHub Release 获取 APK。
- 检查版本、下载 APK、调起系统安装；安装仍需用户确认。
- 禁止把“创建下载任务”当成“正在下载”；升级进度必须来自实际已写入字节。
- 升级 APK 由应用自行流式下载，续传时校验 Content-Range 和服务器校验器，包名与版本校验通过后才能报完成。
- 重复点击复用未完成更新；按版本区分 APK 文件名，避免固定文件名导致再次更新失败。
- 下载完成后保留恢复记录，直到新版本实际安装；允许安装来源后返回应用继续安装，不因取消安装反复弹窗。
- 构建沿用仓库固定正式签名证书；不能把不同签名 APK 当作可覆盖安装的更新。

## 验证记录

- 基础 MPD 解析、Range 地址、寻址继承、多 Period、时间轴偏移、资源身份与取消优先级：已加入单元检查。
- HTTP 实测用例覆盖：暂停续传、忽略 Range、损坏缓存重下、有效片段复用；另检查 HTML 拒绝及版本比较。
- 上述模拟与编译不能代替具体失败链接和真机系统后台行为验证。完成报告应明确区分。
